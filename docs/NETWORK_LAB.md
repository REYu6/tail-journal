# 两个工作节点如何处理同一批宠物模型

这个实验从云端生成 GLB 完成的时刻开始计时。协调器接收任务，两台独立的工作进程通过 HTTP 读取模型、生成 STL，再把结果写回订单。实验使用仓库已有的猫和柯基模型，全部读写真实文件，每次完成后逐字节对照本地顺序转换的参考 STL。

## 运行实验

在项目根目录、macOS 或 Linux 环境执行以下命令。Python 环境须已安装项目的 `requirements.txt`。

```sh
.venv/bin/python -m scripts.network_lab --output network-results.json
```

脚本自行启动一个只监听回环地址的协调器和两个工作进程，每组实验使用新建的临时 SQLite 数据库、私有文件目录和临时节点密钥。它直接写入临时订单和已生成的模型，从调度环节开始。端口由操作系统分配，进程和临时数据在退出时清理。实验不需要模型 API 额度；若省略 `--output`，则只向终端输出测量结果。

| 单独运行 | 内容 |
|---|---|
| `.venv/bin/python -m scripts.network_lab --scenario batch --repeats 3` | 用相同的文件、到达顺序和时间间隔比较三种策略，重复三轮 |
| `.venv/bin/python -m scripts.network_lab --scenario network` | 在传输中给 B 限速，并在另一次传输中恢复链路 |
| `.venv/bin/python -m scripts.network_lab --scenario failover` | 挂起正在处理任务的节点，验证接管、旧节点恢复和迟到写回 |

## 控制变量与测量方法

- 小文件是 `sample-cat.glb`，386,988 字节；大文件是 `studio-corgi.glb`，2,028,148 字节。三种策略使用相同的八个输入，按“大、小、大、小、小、大、大、小”的顺序每 180 毫秒提交一个。
- 批次实验设定 A 的读写上限为 1/2 MiB/s，B 为 6/12 MiB/s。节点实际分块传输并按字节限速，心跳上报有效吞吐。限速作用于本机应用层，链路探测和文件传输共用相同的路径和限速器。
- 批次完工时间从第一单入队算到最后一单归档。每单延迟从它自己入队算到归档。任务 P95 用最近秩计算，八单样本的 P95 是最慢那一单。脚本用独立的新集群运行每种策略，因此各策略不会继承上一轮的队列和测量历史。
- 链路变化实验固定 A 的读写上限为 2/8 MiB/s。B 从 8/16 降为 0.7/1.5，再恢复 8/16。在途任务继续完成。工作进程会从任务传输和空闲探测中更新吞吐；脚本还会在每一阶段分别提交一个小模型和一个大模型并记录实际接单节点。JSON 中的 `observed_after_s` 表示改变限速到脚本观察到有效吞吐变化的时间，包含等待当时在途任务完成的时间。 `large_claim_after_s` 还包含随后小模型的领取与处理时间。
- 故障实验在某一节点领取大模型后发送 `SIGSTOP`，使它的计算和心跳一同暂停。实验租约为 3 秒，在线超时为 2 秒。另一节点接管后恢复旧进程，并携带旧任务版本向同一个 HTTP 发布接口发起迟到写回。脚本核对响应码、订单关联、STL 内容和成功发布事件数。

三种调度策略解决的目标不同。轮流分配均匀分配单数；最短队列倾向待办较少的节点；自适应策略把排队、读取、转换和写回都估算成秒，选预计最早归档的节点。实际写回文件可能比 GLB 大，最近一次转换时间也未必代表下一种网格的计算量，因此应该用实验比较策略，直接观察哪些情况下估算有偏差。

## 一次实测

2026 年 11 月 26 日在 macOS 本机通过回环 HTTP 运行完整实验，两个节点使用同一 Python 3.12 环境。下表为单轮测量，时长包含本地传输、排队、转换和结果归档；真实跨主机部署可以用相同输入另行测量。

| 策略 | 批次完工时间 | 任务 P95 | 八单实际执行节点，按入队顺序 |
|---|---:|---:|---|
| 轮流分配 | 14.533 秒 | 13.448 秒 | A、B、A、B、A、B、A、B |
| 最短队列 | 4.433 秒 | 4.433 秒 | A、B、B、B、B、B、B、B |
| 自适应 | 4.159 秒 | 3.080 秒 | B、A、B、A、B、B、B、A |

这一批中，轮流分配让低带宽 A 接下三个大模型。自适应策略把四个大模型都交给 B，A 同时处理了三个小模型。最短队列在这批输入上的完工时间也接近自适应策略；自适应在此轮的 P95 少了 1.353 秒。

| 链路阶段 | A/B 上报的读取吞吐，MiB/s | 小模型执行节点 | 大模型执行节点 | 自改变限速到大模型领取 |
|---|---|---|---|---:|
| 初始 | 1.943 / 6.038 | B | B | 0.162 秒 |
| B 降速 | 1.846 / 1.001 | B | A | 6.922 秒 |
| B 恢复 | 1.828 / 6.111 | B | B | 2.051 秒 |

故障实验中，B 领取第 1 版任务后暂停，A 在 3.003 秒后取得第 2 版租约。B 恢复后，持旧版本发起的写回收到 HTTP 409。订单只有一次成功发布，归档 STL 与顺序转换结果的 SHA-256 均为 `487fffb1ab0cab15dd1536deedf41dabd6e6457e46686256afce5c137b52a59b`。
